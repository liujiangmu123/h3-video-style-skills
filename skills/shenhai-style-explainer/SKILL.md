# Shenhai-Style Explainer Generator

生产线用：`h3-director` 写深海每一期时读本技能（旁白 + 中文画面 → 原稿 ①②④⑥）。方向、选题、任务消息在研发线的配对 `shenhai-series-planner`；本风格的三层表在 `style-dna.md` B-0。

## 主配方（哲学＝这条可复述的主线；一切细则为它服务）

> **领域锚点容器 1 秒内落位 → 领域实物演示一个核心知识点 → 参数/记号驱动连续变形 → 一句一事件；画布、画面档位与强调色按领域特性分配，符合观看者心理。**

每期每条都走这一条线。题材换到任何领域，配方一条不变——题材只提供锚点容器、实物与物性隐喻，不许改写配方本身。画布、画面档位、强调色、运动质感**不存在固定值**：每个题材现场推导（创意五问 → 画布三问、画面档位、选色三问、运动质感推导，`style-dna.md` Part B），原片里的具体颜色和"只有点线面"的极简，都只是作者对自己题材（平面设计）的推导结果，不是规则——知识住在人、地点、光或材料上的领域，画面要把这些住户画出来（`style-dna.md` B6 画面档位 R1–R4）。

**配方各环节的执行标准**（量化验收值，防止走样，不与配方并列）在 `references/style-dna.md` Part A：锚点怎么落位（A4.9；锚点套件本身由上游任务消息 / 种子包给出，独立使用时按 B-0 五步移植法自行推导）、画布分配后长什么样（A1）、色彩预算多少（A2）、留白多少（A3）、"一句一事件"的节奏数值（A6：事件密度/脉冲时长/静止时长/力度分档/声画反相）、声音与旁白规格（A7/A8）、结构顺序（A9：演示先于命名、三层弧线、互动即最后一例）；A0 是本风格在行业通识尺子上的取舍登记（尺子本体在 `style-foundations` 技能）。"一句一事件"的节拍化模板在 `references/beat-templates.md`。

**哲学与选题四门**在 `style-dna.md` B-0：用一个原理自己的材料，从一个原子开始，演到看懂了再给名字，用真东西作证，最后落到观众手边——全程只动一件东西，旁白不停、画面常停。任何新题材先过四门（原子 / 可演 / 骨架可叠 / 手边），再跑创意五问。

Turn any teaching topic (design, photography, physics, economics...) into a Shenhai-style explainer: a continuously morphing animation with calm narration, generated beat-by-beat with H3. Minimal is the attention design (one change at a time, long dead holds, one late accent) — not a fixed amount of world: how much world the frame holds is derived per field (`style-dna.md` B6).

The style is NOT "edited video". It is **one self-transforming canvas**: pure-animation originals average 0-5 hard cuts in 2-4 minutes. Every transition is an element morphing into the next element. Narration drives rhythm, but sparsely: roughly one short animation pulse every 2-4 seconds (one event per 1-2 sentences), with true freezes between events — an ECG rhythm (pulse — dead silence — pulse), never a conveyor belt of continuous motion. The voice, by contrast, never stops: pauses stay under one second.

**Production pipeline — 配音先行 / 时间码法 (h3-pi-agent docs/26–27).** The narration is recorded FIRST by TTS (`h3_plan_durations`), its sentence cues set the clock, and every animation event in the prompt is pinned to an absolute timecode (`At MM:SS.mmm`, generated by `h3_timecode` from the storyboard + `timing.json`). H3 never hears the audio and never speaks: prompts contain **no `<d>` dialogue, no narrator / voice-over / `(S1)` phrasing, no subtitle bar, no quoted narration text**. Subtitles are not produced by this pipeline (`subtitles` defaults to `none`; the user adds them in post via speech-to-text); BGM, if any, is also added in post (the assembler has no BGM step), so every beat's `non_diegetic_music` is `N/A`. The style block therefore keeps the lower fifth of the frame empty for the post-production subtitles, and every picture field ends with the no-speech sentence (no people at R1–R2; at R3–R4 only the featureless figures the style block registers, `style-dna.md` B4). The rhythm law above is unchanged by this — a sentence that triggers no event is written `→ 视觉：（静止）` in the script (the storyboard marks it `still`, `h3_storyboard set still=true`) and gets no timecode; the picture still rests under a talking voice.

## 输入与输出 · one episode in, one production package out

**Input (one episode).** Normally a topic entry handed over by the planning skill (任务消息 / 开工种子包 / 路线图 row): 期号、标题、一句话钩子、核心知识点、四门三元组（原理 / 证物 / 手边物）、主锚点、爆款指数、钩子类型、**创新档 A/B/C**、查证要点; plus the channel's locked parameters: canvas mode and accent derivation words (never hex), the field's register and range (`style-dna.md` B6) with its inhabitant bible, 3-5 domain anchors, long-form duration and aspect, short-form duration and aspect, special red lines; plus optional reference images for Ref2VA. Standalone use: the user gives topic + duration + aspect and this skill derives everything else in Workflow step 2-3.

**Output (one episode = one markdown file).** **In the H3 pipeline (Pi / `h3_*` tools) the manuscript is ① ② ④ ⑥** — ③ and ⑤ are not written by hand: after `h3_new_episode` the English picture goes into the storyboard (`h3-storyboard-writing`), the narration is recorded, and `h3_timecode` assembles every segment prompt from the recorded cues (the parser does not read a ③ chapter, and `At MM:SS.mmm` cannot exist before the recording). Only a standalone delivery that will not go through the tools writes all six parts:

Append **assembly notes** after ⑥: segment order and continuation chain, the `h3_align` sync verdict per segment (pass / check / fail), and the assembly instruction `h3_assemble audio=mix` — narration on the main track, H3 event sounds normalized and ducked, no subtitles burned (the lower band stays empty for post-production subtitles; BGM also in post). Standalone (non-pipeline) deliveries note instead which beat boundaries use I2VA / FL2VA and which frame to extract.

**Where the two shared skills sit.** `creative-animation-treatment` is invoked only for tier C (or when the 创意五问 answer to question 4 makes form-is-content obvious); it returns a *treatment* in its own format (register, world and inhabitant bible, inner verb, adopted look, four testable craft rules, signature moment, world-class gate score, hook frame, first-10-seconds) — never prompts. Below tier C the register is still derived here (B6) and the style block still written at full density. This skill translates that treatment into beats; in the pipeline each beat's picture is written as storyboard sentences (`h3-storyboard-writing`) and `h3_timecode` produces the prompt, standalone prompts use `h3-prompt-writing`'s official field structure. The treatment must respect what one H3 shot can do (single `[Shot 1]`, locked camera, morph verbs, events ≳1.2 s apart, ≤15 s, stated duration) — that is what "creativity under H3 guidance" means. On field names and order the official `h3-prompt-writing` is the last word; on the timecode line's own conventions (no `<d>`, `At MM:SS.mmm`, closing sentence) `h3-storyboard-writing` §9 is.

## Workflow

1. **Read the style DNA and the hit mechanics** — read `references/style-dna.md` before writing any prompt. It opens with THE FORMULA (the master recipe every beat follows), then the per-stage execution standards (canvas, quantified color budgets, composition, the ECG rhythm numbers) and the reusable English style block. Then read `references/hit-mechanics.md` so every choice below can be judged by which audience mechanism it serves (gap at 0.3 s / show-before-name / evidence with skeleton / back in the viewer's hand / stillness under a continuous voice).
2. **Interview the topic** (ask user only if missing): topic, target duration, whether platform interaction prompts (like/subscribe) should be included, aspect ratio (default 16:9). First run the topic through the **Four Gates** (`style-dna.md` B-0: atom / demonstrable in 20s / skeleton over real evidence / in the viewer's hand) — a topic failing gate 1 or 2 is not a Shenhai topic. Canvas, register, accent color and motion texture are NOT free choices to ask for — run the 创意五问 brief (`style-dna.md` B0, starting with question 0: where does the knowledge live?), then derive canvas via 画布三问 (B1), the register R1–R4 via B6 (how much world the frame holds: signs / cutaway / silhouette stage / cut paper — the originals' signs-only minimalism is R1, right for fields whose knowledge *is* signs and wrong for fields whose knowledge lives in people, places, light or matter), accent via 选色三问 (B2) and motion verbs/weights via B5, and confirm the derivations with the user. **Domain anchor kit**: when the request arrives from the planning layer (a 任务消息 or 开工种子包), the kit, the field's register and range, the episode's 四门三元组 and its 创新档 are already in the brief — use them as given (the episode may move one step inside the range with a reason written in ①, B6). When used standalone on a non-design topic, derive the kit yourself with the five-step transplant in `style-dna.md` B-0 before inventing beats.
3. **Set the innovation tier** (创新档, from the brief; self-judge only when there is none — see `hit-mechanics.md` §4):
   - **A 常规** — go straight to step 4 with the default recipe.
   - **B 母题创新** — fix the one graphic device that carries the whole film (A9.4) and write it into the style block and every beat; numbers untouched.
   - **C 形式即内容** — invoke the `creative-animation-treatment` skill in whole-film mode: hand it the topic, the brief, the **tier-1 row of the B-0 three-tier table as unbreakable constraints**, tier 2 as the base it departs from with reasons, and the **B6 register range**; accept only treatments that pass its world-class gate (≥24/30, no layer ≤1) and keep tier 1. Then continue below with that treatment as the motif.
   - **Every tier, every register**: write the episode's style block at full density before the beats (`style-dna.md` B4 register blocks; slot list in `h3-prompt-writing` creative-compile §7). The world lives there, written once; the beats only carry what changes.
4. **Write the script skeleton** using the seven-part narrative structure (below). Write narration as short Chinese sentences of 5-15 characters, paired and contrastive. Budget **≈ target seconds × 3.5 characters** (a 150 s film ≈ 550 characters); the narration is brisk and continuous, with pauses under one second. (The reference films run ≈5 chars/s, but the production TTS — MiniMax Credible Alex at speed 0.96 with gapSentence 0.24 / gapSegment 0.9 and 17k+5 grid snapping — measures ≈4.4 chars/s inside a sentence and ≈3-3.7 chars/s over the runtime, so a ×5 budget renders ≈30% too long; `G:\AI\H3动画量产_AI总指导.md` §4.2. The recording is always the final word on length.) Open with one of the eight hook patterns in `hit-mechanics.md` §3 and write the viewer's one-line "原来如此" before drafting further. Pair every sentence with a one-line Chinese picture description ("what happens on canvas while this is said" — or （静止）) and its event sound. **Write no seconds and no segment lengths** — time does not exist yet at this step; it is created by the recording in step 6.
5. **Cut the script into beats** (segments) of roughly 2-5 sentences each (≈8-15 s once recorded; ≤15 s, 12 s common). Each beat = one H3 generation. Assign each beat a beat type (B1-B8) and fill the beat table (see `references/beat-templates.md`). In the tool pipeline this is `h3_new_episode … storyboard=true`, then `h3_storyboard set` fills every non-still sentence's English `visual_en` + `sfx_en` — the ② chapter format the parser accepts (`【第 N 段 | … | 拍型：…】` / `整句 → 视觉：…`; `（静止）` = `still`, no `visual_en`, no timecode) and the `visual_en` wording are in skill `h3-storyboard-writing` and `G:\AI\H3动画量产_AI总指导.md` §4.3.
6. **Record the narration first and derive durations**: `h3_plan_durations` runs TTS at natural speed, sets each segment's duration to `grid(speech + gapSegment)` (17k+5 frames @24fps, snapped up) and writes the sentence cues to `timing.json`. Never compress or stretch the narration to fit a picture length — the picture follows the voice.
7. **Write one H3 prompt per beat** — in the pipeline `h3_timecode` assembles it from the storyboard + cues (timecode formula, `finishing by`, freeze / closing / no-speech sentences, field order: `G:\AI\H3动画量产_AI总指导.md` §7 and skill `h3-storyboard-writing`; standalone prompts: official field grammar in `h3-prompt-writing`, timecode conventions in `h3-storyboard-writing` §9), and `references/beat-templates.md` shows what goes inside the fields. Before writing the motion sentences of a beat, run the **feel layer** (`style-dna.md` B5.4 → `creative-animation-treatment/references/feel.md` §一/§二). B5.4 sorts the author's answers into essence (dead holds, one mover, color as event — never overridden) and **author defaults** (no wind-up, three envelope families, temporal imperfection, no shadows, camera holds) which are the base every beat starts from and **may leave when the topic's material or the demonstration asks for it** — written as a device with its reason, never as a habit. **Production translation of the envelopes:** the originals glide 0.5-0.8 s with a verb-specific envelope. Production writes the **mixed** motion_rule (`h3-storyboard-writing` §6): crisp quarter-second changes for appearances, fills and colour, and a steady move that stops dead at a written `until` for the few beats where the movement *is* the demonstration (a frame stretching, a tail lowering, a frame turning into a phone). An all-crisp film has no process to watch; an all-glide film smears fills into brush strokes and starts late (10-01 draft A/B, `h3-production-lessons` T-004). The feel lives in what changes, the dead hold before it and how it ends (the ending names the material). Envelopes (fast attack + elastic settle, draw-on) are written only in a declared gradual style — motion_rule rewritten, `compensation_s` ≈ −0.5, re-measured with `h3_align`. A grouped entry is ONE timed event whose clause says the items enter one after another ("three cards snap in one after another, the last a hair late") — H3 merges two small actions written ≲1.2 s apart. The longest hold sits *before* the beat's key event; the accent's first arrival is placed on a named word; each beat names its one invisible detail. A vague verb ("slides in / fades in / moves") is a draft, not a prompt: use `instantly pops in / snaps into place / changes into` (`h3-storyboard-writing` §2), and write every morph with its start and end form.
8. **Chain the beats**: the production pipeline chains beats by latent continuation (segment N+1 starts from segment N's tail), so state in the prompt that the opening layout continues from the previous beat and end every beat on a still frame. Standalone use (no pipeline) may fall back to I2VA / FL2VA with extracted frames.
9. **Render, then verify sync** with `h3_align` (frame-difference motion onsets vs. the written timecodes; pass = every timecode matched, median offset ≤0.2 s and max ≤0.3 s; check = matched, median ≤0.35 s; otherwise fail). Systematic offset → apply `suggest_compensation_s` (measured against the narration; default +0.2), regenerate the prompt with `h3_timecode`, re-render from segment 1 (the frozen fingerprint covers the whole film) with the same seeds. Never fix a lag by editing the narration.
10. **Short-form pass** (when the brief asks for 抖音版, which the production line always does): compress ② into a 55-70 s 9:16 narration whose first sentence is a question / contrast / negation, re-check every compressed sentence against the ① fact record (compression is where facts flip), then cut it into 4-6 beats and run steps 5-9 on it the same way (its own TTS recording, its own `timing.json`).
11. **Self-check** every prompt against the Quality Checklist and the five-point self-test in `hit-mechanics.md` §5, then deliver the package defined in 输入与输出 above — pipeline: one markdown file ① 选题信息与查证记录 → ② 长版旁白时间轴 → ④ 抖音版旁白时间轴 → ⑥ 自检表 (the prompts come from `h3_timecode`); standalone: all six parts + assembly notes. Assembly (`h3_assemble audio=mix`) puts the narration on the main track and normalizes and ducks H3's event sounds; subtitles and BGM are added by the user in post.

## Seven-Part Narrative Structure

| # | Part | Duration | Content rule |
|---|------|----------|--------------|
| 1 | Cold open | 3-6s | No greeting. "这是X / 这是Y" paired definition of the topic's most atomic element, shown alone on canvas |
| 2 | Concept build | 10-30s | Paired attribute contrast (straight/tilted, line/plane, 2D/3D...) shown by morphing — **the phenomenon runs before it is named**; the first term card lands at 12-27s in the originals, never inside the first 10s (style-dna A9.1) |
| 3 | Case ladder | 50-70% of runtime | Evidence chain: art history → design history → brand logos → modern products/UI, each shown with the principle's construction lines drawn over the real object (A9.2) |
| 4 | Concept cards | 5-10s each | Professional term as a bilingual typography card at chapter turns, always after its demonstration |
| 5 | Interaction plant | 5-8s | Platform like/subscribe button itself becomes a subject-matter example — the last proof that the principle reaches the viewer's hand (A9.3); may sit at 60% of runtime or at the end (optional). Only when the button really behaves that way; otherwise use a device the viewer owns (phone camera, video call). Never invent a button behaviour |
| 6 | Aphorism | 3-5s | One philosophical closing line about the discipline |
| 7 | Fixed outro | ~5s | "感谢大家看到这里…一键三连，我们下期再见" + tri-icon animation |

To adapt a new topic, fill this mapping first (or take it from the upstream brief): atomic element (photography → a beam of light / an aperture blade), attribute pair (large/small aperture), case ladder (painting chiaroscuro → classic cameras → phone camera UI), concept terms (Bokeh, Sunny 16), interaction plant (long-press like = shutter click), **domain anchor kit** (3-5 recurring domain-native containers/notations/tools — photography: viewfinder corner brackets, exposure readout "1/125 · f/2.8 · ISO 100", white-bordered photo prints, flat vector camera). Derivation method: `style-dna.md` B-0 five-step transplant.

## Hard Rules (violating any one breaks the style)

- **Zero cuts inside a beat**: every beat is a single `[Shot 1]`, no `[Shot 2]`. All change is morphing, sliding, drawing-on, or scaling of elements. **Camera perfectly locked in production** (default motion_rule: no zoom, no pan, no camera drift). The originals had rare slow small-amplitude zooms; never write them into the timecode line — `h3_align`'s frame diff reads camera motion as whole-frame motion and loses the event onsets.
- **Domain anchors in every beat**: Shenhai's own subject IS graphic design, so abstract shapes are his content for free; any other topic must earn recognizability explicitly. Every beat must show at least one item from the topic's domain anchor kit (container, notation, tool, or iconic imagery), and the cold open's abstract atom must be captured inside a domain container within that same beat. Anchors are drawn in the episode's register language (B6) and obey the tonal body + single accent rule. Test: a viewer seeing any single beat with the sound off should still name the video's field. **A container is not a demonstration**: the knowledge must be shown on what lives inside it — the field's own people, objects or works. If swapping those inhabitants for dots would leave the lesson intact, it was never in the picture; if it would kill the lesson, the inhabitants must be drawn.
- **The register is derived, never inherited** (`style-dna.md` B6). R1 signs is the originals' world and stays right for fields whose knowledge *is* signs; R2 cutaway, R3 silhouette stage and R4 cut paper are the same grammar sized to fields whose knowledge lives in machines, people, places or matter. Range R1–R4 (R5 cinematic 3D is a style variant). One register per episode. Whatever the register, tier 1 holds: one change at a time, everything that carries information dead still between events, one late accent, zero cuts, locked camera, a made world with no realistic faces.
- **One accent color per video**, stated identically in every beat prompt. Everything else stays black/white/grey. Semantic colors fixed: red = wrong/old, green = correct. **The accent lands as a surface at least once per chapter** (a filled area, a highlight under the chosen thing, the top face of a shape — not only a thin outline): the originals' single-accent standard tier is 8-17 % colored area, and `h3_align` warns when the film's p90 colored area stays under the style's `target_color_area`.
- **The recipe's third link must be on screen — a parameter or notation drives the morph.** Every episode has one visible number, ratio, unit, angle or label (an aspect-ratio readout "4 : 3 → 2.39 : 1", an f-number, a degree mark, a count) that changes and *causes* the shape to change; the hero morph of each chapter is driven by it. An episode where things only appear and disappear has dropped 配方 step 3 and reads as a slideshow.
- **Canvas is a lit place, locked per chapter** (at R3–R4 the place is the literal set, lit by one named key light, B1 note; mode derived via 画布三问: light "paper" — paper-grey a step below pure white with layered whites — or dark "blackboard/darkroom" — warm near-black with a soft central light pool and darker corners; always a faint micro grain, never dead-flat, never pure extremes). Switching light↔dark is allowed ONLY at a concept-card chapter turn as a deliberate chapter accent (6 of 11 originals do exactly this: light teaches concepts, dark hosts glowing demos); never switch mid-chapter.
- **Subtitles are added in post, never written into the prompt**: the finished film still shows a bottom-center subtitle band every second (one short sentence at a time, synchronized with narration), but the user adds it after delivery via speech-to-text; the pipeline delivers without subtitles (`subtitles=none` default). No "subtitle bar", "caption bar" or quoted narration text on canvas; instead the style block keeps **the lower fifth of the frame completely empty at all times** so the subtitle band has a clean home. The only on-screen text is content text (labels, concept cards) in exact quotes.
- **Narration is an external voice track, never in the prompt**: no `<d>…</d>` dialogue, no "narrator", "voiceover", "(S1)" or "says" phrasing. The voice is one calm young-adult male TTS voice recorded first — brisk and continuous (reference films ≈5 chars/sec, 6-7 while voicing; our MiniMax voice ≈4.4 inside a sentence, so budget ×3.5 of runtime), breath pauses under 1s, first sentence at 0.3s, short declarative sentences, no greeting — and its sentence cues (`timing.json`) drive the timecodes. Every prompt ends the picture field with `No speech, no dialogue, no human voice of any kind; no people or faces appear; no on-screen text other than the labels described.` — except when the episode has a silhouette cast or paper figures (R3–R4): then the episode style overrides `no_voice_en` with the register sentence in `style-dna.md` B4 (still starts with no speech / no dialogue / no human voice; allows only the featureless figures described, mouths closed).
- **Every event carries an absolute timecode**: `At MM:SS.mmm, {element} {action} with {sound}, then the canvas freezes.` — timecode = the triggering sentence's start within the segment, plus `compensation_s` (default +0.2 s with the locked-camera / instant-appearance motion rule, measured 2026-09-27; about −0.5 s only for gradual draw-on styles), plus the 0.917 s continuation head for segments ≥2. The first event of a segment is never earlier than 0.300 in segment 1 / 1.217 in segments ≥2 (writing 0.050 makes H3 start *later*). Long actions (stroke-by-stroke drawing, gradual reveals) get an explicit end — `…, finishing by MM:SS.mmm` — otherwise H3 keeps drawing and pushes every later event back. Timecodes strictly increase; the last one stays ≥0.5 s before the segment end and ends "and everything holds completely still until the end". Keep ≤6 timecodes per segment.
- **At most one event per sentence, one event per 1-2 sentences — ECG version.** The event is a short crisp pulse — the originals glide 0.5-0.8 s with a verb-specific envelope (style-dna A6); production writes it as the default motion_rule's single crisp change completed within a quarter second (best measured alignment), and envelopes (fast attack + elastic settle, draw-on) only in a declared gradual style with `compensation_s` ≈ −0.5, re-measured with `h3_align` — and the canvas FREEZES completely before and after it (zero pixels moving, no idle loops, no ambient drift) — write "then the canvas freezes" after every event. At least a third of sentences pass with nothing moving at all (written `→ 视觉：（静止）`, storyboard `still`, no timecode); still gaps of 1-3s are the norm, holds of 4-10s are routine, and one 10-30s hold per film is allowed while the voice keeps talking — never fear stillness, fear filling it. At any moment at most ONE element moves; a grouped entry (the originals stagger 0.2-0.4 s) is written as ONE timed event whose clause says the items enter one after another ("three cards snap in one after another, the last a hair late") — never as separate timecodes 0.2-0.4 s apart, because H3 merges two small actions written ≲1.2 s apart. One hero-tier event per chapter, everything else stays normal or micro tier. The voice never rests to "let the picture breathe" — the picture rests under a talking voice (A6 声画反相). **Production rhythm budget (2026-10-01):** "one event per 1-2 sentences" is a ceiling per sentence, not a target — write to the originals' density: at least the style's `target_events_per_min` over the film (17/min since 10-01, pixel metric, `h3-storyboard-writing` §6 — about 0.6–0.7 events per sentence with our TTS; about a third of sentences still), events on the sentence onset or on the key noun (`at` 0.4-0.7). `h3_timecode` prints a 节奏预检 (events/min, motion share, still median) against the style's `target_*` keys and `h3_align` prints the measured 成片读数; writing "events fewer than sentences" alone produced 5-7 events/min and 1-2 % motion in the 09-30 episodes. Every change must have visible area (fills, solid↔dashed, morphs of block shapes); a thin line nudged a little is not an event to the eye or to the metric.
- **Audio**: sparse UI sounds (soft whoosh/pop/tick) only on animation events, written inline with the action and listed again by timecode in `overall_soundscape`, ending with "Quiet room tone underneath; no voices."; `non_diegetic_music: N/A` — no music is generated per beat or at assembly; any lo-fi bed is added by the user in post.
- Real famous artworks/products: in the **timecode-method production line (no reference images) `<Picture N>` is forbidden** — describe the work as a "flat vector redraw in uniform black strokes" (R1–R2) or re-stage it in the episode's register (R3–R4: the blocking and one signature prop with the silhouette cast; never a frame copy, facial features, original colours, subtitles or sound) to keep visuals clean and rights-safe. `<Picture N>` / Ref2VA is only for the standalone scenario where the user actually supplies the images.

## Quality Checklist (run per beat — in the pipeline on the storyboard and on `h3_timecode preview`)

- [ ] Single `[Shot 1]`, no cut words, no camera-move words (zoom / pan / dolly); crisp change verbs present (`instantly pops in / snaps into place / changes into / flips to`, `h3-storyboard-writing` §2), every morph written with its start and end form ("the X changes into Y"); no `slowly / gently drifts / gradually`
- [ ] Style block present and identical across beats (canvas descriptor, accent color phrase, "lower fifth stays empty", motion rule, watermark corner clear); no hard-coded hex values in hand-written blocks — accent stated as the 选色三问 derivation result in words
- [ ] Narration lines: Chinese, 5-15 chars each, total chars ≈ target seconds × 3.5, one per line in `旁白脚本_长版.txt`; no pause written longer than 1s except at one chapter turn; recorded by TTS first — **none of it appears in the prompt** (no `<d>`, no narrator/voiceover/(S1), no subtitle bar, no quoted narration text)
- [ ] Every event has an `At MM:SS.mmm` timecode taken from `timing.json` cues (compensation / continuation head applied; first ≥0.300 in segment 1, ≥1.217 in segments ≥2), timecodes strictly increase, last one ≥0.5 s before segment end, ≤6 per segment; long actions carry `finishing by`
- [ ] Structure: no term card inside the first 10s; the first concept card follows its demonstration; the interaction plant (if any) is written as a subject-matter example, not an appended CTA
- [ ] Concept card (if any): exact bilingual text quoted, highlight/underline in accent color described
- [ ] Animation events: at most one per sentence and roughly one per 1-2 sentences, written as short pulses with "then the canvas freezes" between them; at least a third of the beat's sentences have no event; each event is the default single crisp change within a quarter second (named envelopes — slide = fast attack + elastic settle, draw-on = accelerate and stop dead — only in a declared gradual style with compensation ≈ −0.5, re-measured); at most one element moving at any moment; a grouped entry is one timed event ("one after another, the last a hair late"), no two timecodes ≲1.2 s apart
- [ ] Feel layer (`feel.md` §六 six tests): every move states what precedes it and how it stops; a grouped entry's clause names the order and a late last item; the longest hold of the beat precedes its key event; the beat names its one invisible detail; none of the mediocre defaults (uniform easing, equal cascade, idle drift, glow/bloom, fade-as-transition, unmotivated zoom) survives
- [ ] Picture field ends with the no-speech / no-extra-text sentence (`no_voice_en`): no people at R1–R2; at R3–R4 the register sentence that allows only the featureless figures described
- [ ] `overall_soundscape`: only sparse UI sounds listed by timecode + "Quiet room tone underneath; no voices."; no music here
- [ ] `non_diegetic_music: N/A` (no BGM generated; the user adds any in post)
- [ ] Duration = `grid(speech + gapSegment)` from `h3_plan_durations`, never hand-estimated from character count (standalone I2VA / FL2VA only: duration stated and consistent with the alignment timestamps, two decimals)
- [ ] Beat boundary: first visual state matches previous beat's final state (or is a deliberate clean start on the same canvas)
- [ ] Domain anchor present: at least one domain container/notation/tool visible in this beat; the field is recognizable from the visuals alone
- [ ] Register (B6): the episode's register is written in ① with its reason and sits in the field's range; the replace-with-dots test fails (the lesson needs the inhabitants that are drawn); the style block is the register block at full density (place and depth planes, inhabitant bible, key light and shadow direction, material, bed of sound), not the default R1 block reused for a non-R1 field; `no_voice_en`, `hold_en`, `closing_en` and `sound_suffix` match the register
- [ ] Not mediocre: run `creative-animation-treatment/references/world-class.md` §〇 on the beat table — three or more hits (empty frame, clip-art inhabitants, every change a switch, no light, no frame worth a screenshot…) means rewrite before rendering
- [ ] Recipe step 3 present: one visible parameter / notation changes and drives the chapter's hero morph
- [ ] Rhythm budget: `h3_timecode` 节奏预检 has no ⚠ (≥ target events/min, motion share, still median); after rendering, `h3_align` 成片读数 events/min, motion share, ink and colored area are inside the style's targets — if not, the changes are too small or the accent never became a surface

## Failure Handling（生成结果不对时：症状 → 提示词矫正）

- 画面动个不停、没有静止感 → 提示词里显式写冻结：每个事件后加 "then the canvas holds perfectly still / freezes completely"，并删掉一切 ambient/idle/drift 措辞；数一下本拍的事件数——应当少于句数（每 1–2 句一个），多余事件的句子改成 `→ 视觉：（静止）`（分镜 still=true），而不是压短。
- 所有动作软绵绵、节奏平 → 删掉 "smooth ease-out / slowly / gradually" 措辞，回到默认 motion_rule 的清脆动词（instantly pops in / snaps into place / changes into，四分之一秒内完成）；把本拍的力度档写清（micro/normal/hero）——力度靠变化的面积和反差，hero 拍写整幅 "burst" 级变化，不靠拉长动作。只有声明了渐进风格（改写 motion_rule、`compensation_s` ≈ −0.5、`h3_align` 复测）才按动词写包络：位移入场 "a fast attack and a longer elastic settle"，逐笔画出 "the stroke accelerates and stops dead the instant it completes"。
- 旁白拖、画面空 → 字数按 目标秒数×3.5 复核（配音实测为准）；每句 5–15 字、句间停顿不写超过 1 秒；不要为了"让画面呼吸"而让旁白停——画面在旁白之下呼吸。
- 一开场就出术语卡 → 把卡片挪到现象演示之后（原片 12–27 s），前 10 秒只允许原子和它的第一次变化。
- 多个元素同时在动 → 同一组入场写成**一个**时间码事件，先后顺序写在从句里：`three cards snap in one after another, the last a hair late`（原片错开 0.2–0.4 s，但 H3 会把相隔 ≲1.2 s 的两个小动作并成一个，所以不给每件各写时间码）；不属于同一组的动作拆到不同句、相隔 ≥1.2 s。
- 出现第二种彩色 / 颜色泛滥 → 每拍开头重申 "a single {ACCENT} accent color; everything else strictly black, white and grey"；检查是否误用了带色彩联想的名词（golden light、blue sky）。
- 画布死平像 PPT → 用 B4 style block 的完整画布句（光池/层次白/微噪点），不要简写成 "grey background"。
- 领域认不出（看着像抽象图形展）→ 检查锚点是否写进了这一拍：至少一个 domain container/notation/tool 必须出现在视觉描述里，而不是只在脑子里。
- 看得出领域、看不懂知识（容器里只有圆点 / 标签 / 剪贴画）→ 住户缺失：换成本领域的具体住户（人、器物、作品），按 B6 把档位升到知识所在的那一档。
- "元素极其简单 / 像信息图 / 动画中等"（2026-10-01 画框期用户原话）→ 不是动作不够多：多半是档位低于知识、风格块没写世界。按 B6 重定档位，用 B4 档位块满配重写风格块（地点与景深层、住户圣经、主光与影子朝向、材质、声音底），再按 `creative-animation-treatment` world-class.md §三 过一遍门槛；事件密度照旧按 A6。
- H3 自己画了字幕条 / 出了人声 / 念了旁白 → 提示词里混进了旧写法：删掉一切 `<d>`、subtitle bar、narrator/voiceover/(S1) 措辞，确认末尾有 "No speech, no dialogue, no human voice of any kind; …"（R1–R2 接 "no people or faces appear"，R3–R4 有剪影演员时接 B4 的放开句），并把风格块里的"底部五分之一留空"句写全（字幕由用户后期语音转文字自做，产线不烧）。
- 剪影演员长出五官 / 手指，或被画成写实人 → `no_voice_en` 用 B4 的 R3 句；住户圣经那一句写明 featureless、only the outline of nose and chin；不写 man / woman / person，只用圣经里的称呼；段 ≥2 只点名不重述。
- 动作整体比配音早/晚 0.1 s 以上（`h3_align` 报系统性偏移，口径已改为对配音开口）→ 不要改配音：按 `suggest_compensation_s` 改 `compensation_s`（默认 +0.2；渐进描画类约 −0.5），`h3_timecode` 重写后从段 1 同 seed 重跑；某个时间码没检到动作 → 该事件动作太轻或被忽略，加大幅度 / 换更明确的动词。
- 段 ≥2 开头动作比预期早约 0.9 s → 忘了续接头：段 ≥2 的写入时间码要加 `continuation_head_s`（默认 0.917 s），`h3_timecode` 会自动加。
- 长动作（逐笔画出、渐显）把后面的事件全推迟 → 给它写死终点 `…, finishing by MM:SS.mmm`；一段之内时间码不超过 6 个。
- 元素乱变形、morph 目标错 → 形变句写清起点和终点两个形态，用 `the X instantly changes into Y`（要过程时 `one single shape changing continuously in place, until it has become Y`），不写 morph——`morphs … finishing by` 被画成两个半透明形叠化、数量也变了（`h3-production-lessons` P-016）；一次只变一个对象；同一拍前面不要先把这个对象的外框抹掉（P-014）。
- 镜头乱动 → 重申默认 motion_rule "One continuous shot with a perfectly locked camera: no zoom, no pan, no camera drift"；删掉任何 zoom/pan/orbit/dolly 词（原片偶有慢速小幅推镜，但时间码线里不写：`h3_align` 帧差会把镜头运动当成整幅画面在动）。
- 出现真实照片质感 → 强化本期档位块的材质句（R1：`flat vector, uniform-weight strokes, no gradient, no shadow`；R3：`flat matte shapes in close grey steps, shadows drawn as flat crisp-edged shapes`；R4：`matte cut paper and card with visible thickness`）；引用资产时确认写了 rounded-card 容器或档位里的重演写法。
